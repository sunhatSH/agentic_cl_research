## 六、选型结论

**当前选择：`openai/gpt-5.6-luna`**（已写入 `configs/agents.yaml`）。

### 选型理由

1. **gemini 直接淘汰**。扣分 prompt 对其完全无效——correctness 依然 83% 在 1.0，reward 0.89 与旧 prompt 的 0.88 无差异。训练中 reward_max 恒为 1.0，天花板被封死。稳定性 0.006 虽极端但打分无效，相当于每次都稳定地给所有人 1.0。

2. **deepseek 也不够好**。扣分 prompt 下 correctness 仍有 63% 在 1.0，reward 0.80 相对旧 prompt 的 0.79 下降微弱。延迟 19.5s 是三模型中最高的。

3. **gpt-5.6-luna 是唯一有效果的**。扣分 prompt 下 reward 从旧 prompt 的 0.69 降到 0.56，correctness=1.0 占比从 85% 降到 10%，分布真正拉开（0.1–1.0 全覆盖）。within-rw std 0.082 比 gemini 的 0.006 大，但这是 gpt 真正在区分轨迹优劣的结果——gemini 的 0.006 是"每次都打满分"的伪稳定。

### 风险

- gpt 的 within-rw std 0.082 意味着同一轨迹重复打分波动约 ±0.08，在可接受范围但高于 gemini。训练中通过 GRPO 组内归一化可部分吸收此噪声。
- 如果 gpt 的实际 reward_mean 仍偏高（如 >0.8），可进一步调整奖励公式（如将 done 基线分从 0.2 降到 0.1 或 0）。
