## 2. 两条推理路径（别混）

| 路径 | 谁推理 | 在哪跑 | 调什么模型 | endpoint |
|---|---|---|---|---|
| **A. 训练 actor（正式）** | verl rollout LLM server | 训练集群 GPU | **Qwen3.6-27B**（本地权重） | verl 内部 `LLMServerClient`（不走 HTTP） |
| **B. 沙箱采集 actor（冷启动/对照）** | **沙箱内 hermes** | 腾讯沙箱 Instance | gpt-5.1（或 `agents.yaml` 定的） | `AGENT_MODEL_BASE`（沙箱可达的 OpenAI 兼容 endpoint） |

- 路径 A 是**正式训练**：verl 原生 rollout 产出 token + logprob，token/logprob 直接进 buffer，不经过沙箱。
- 路径 B 是**冷启动采集 / 远程对照**：hermes 在沙箱里跑 ReAct（调模型 + 执行工具），产 trajectory 入 replay buffer 预热。`scripts/sandbox_grpo_collect.py --actor hermes` 走这条。

## 3. 三个开发机侧 Agent（都在开发机跑，直连 tokenhub）

| Agent | 模型 | 作用 | 配置 |
|---|---|---|---|
| **Observer** | gpt-4.1-mini @0.0 | 取证：沙箱 before/after diff 为 ground truth，产 ObservationReport | `agents.yaml: observer` |
| **Questioner** | claude-sonnet-4-6 + 轮换池 @0.9 | 模拟用户出 follow-up query | `agents.yaml: questioner.rotation` |
| **Reward/Judge** | claude-opus-4-8-thinking @0.0 | 三维打分 → reward | `agents.yaml: reward` |

> Observer 默认 `use_llm=False`（确定性取证、零模型调用）；只有需要模型归纳时才调 gpt-4.1-mini。

## 4. 一次 8 路 GRPO 采集的完整流程

```
1. 起 8 个沙箱（同 v2 镜像、同 persona/seed，位级一致起点）
2. 对每个 query（共 N 个，顺序）:
   a. 8 路并行：每个沙箱里 hermes chat -q "<query>"
      → hermes 调模型决策 + 沙箱内执行工具(python/bash/文件)
      → 产 1 条 trajectory (messages + answer)
   b. 开发机 reward judge 对 8 条轨迹打分
   c. GRPO advantage 归一化 + select_winner → winner 固化
   d. sync_to_winner: loser 沙箱状态对齐 winner + history 累加
3. session 结束: destroy 8 沙箱
4. 轨迹落盘 rollouts/grpo/grpo_<actor>.jsonl + manifest.json
```

## 5. reward 公式（与 ClawEval 评测同构）

```
verdict = {completion, safety, robustness}   各 ∈ [0,1]，judge 模型输出
reward  = safety × (0.8·completion + 0.2·robustness)
```
- **completion 锚定沙箱 diff（真实产物）**，不看 actor 自称 → 反 reward-hacking
- safety 乘性门控：不安全直接 0
- judge 全程冻结（跑数周/多实验测遗忘，避免版本漂移）

## 6. 训练侧消费（rollout → buffer → loss）

```
trajectory (messages + token_ids + logprobs + reward + bucket)
   → trajectory_adapter 转成 verl DataProto
   → 7 桶 Replay Buffer（按能力域分桶，桶内淘汰禁跨桶）
   → CL Loss: L_rl + L_kl + L_replay(从 buffer 采) + L_ent
   → verl PPO 更新策略
```
