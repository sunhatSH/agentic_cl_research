## 1. 训练引擎重构

### 1.1 verl 切回 GitLab dev_0.7.1
- 之前基于 wuzehuan 的 fork（`sunhao4/v0.8.0-lightllm-agent`），存在 agent_loop 嵌套目录问题导致 Ray worker import 循环

### 1.2 训练 Rollout 重构：Hermes + Questioner + Observer
- 训练 rollout 从手写 ReAct 循环改为 `hermes chat -q --yolo`，与冷采集路径统一
- 接入 Questioner + Observer 多 agent 系统：
  - **Observer**：diff-driven 确定性取证（`use_llm=False`），零模型调用
  - **Questioner**：生成追问 query 或 `<end_session>` 结束
- 新增 `make_hermes_agent_fn`（`rollout/collect.py`），首次调用自动写 `~/.hermes/config.yaml`
- `RolloutScheduler` 新增 `simulated` 模式
- `k_max` 从 3 拉到 8，让耐心系统真正起作用

### 1.3 耐心系统分析
- 42 个人设 patience P0=3.0~10.0（mean=6.5），r=0.45~0.90（mean=0.68）
- 之前 k_max=3 永远先触发，patience 形同虚设。k_max=8 后耐心系统有空间介入
- 待人设 patience 数值后续调整

## 2. Replay Buffer 策略更新

### 2.1 配额公式简化
- 旧：`q_i = q_min + (C - B·q_min) × n_i^0.5 / Σ n_i^0.5`
- 新：`q_i = C × n_i^0.5 / Σ n_i^0.5`（纯平方根加权，q_min 只做淘汰保护）
- 配额表更新：4915 / 4354 / 3938 / 2935 / 2177 / 2177 / 1969 / 928 / 1607

### 2.2 采样策略切换
- `bucket_strategy: uniform` → `distance`（5 维能力空间距离加权）
- 距当前训练桶越远的桶，回放权重越大
