## 一、一句话定位

线上 agent 每 ~2 周用新回流数据做一次 GRPO 更新，这是一个 **task-agnostic 的持续强化学习**问题。朴素地把 GRPO 搬进来会同时撞上两类失败：

- **灾难性遗忘**：新任务的更新系统性侵蚀旧领域能力。
- **Echo Trap**：多轮 agent RL 中策略多样性坍缩 → 组内轨迹趋同 → GRPO advantage 退化 → 训练崩溃。

我们的方案：**先在源头产出干净训练信号，再用匹配的方法巩固**——五个相互独立又彼此咬合的设计，全部以零源码改动注入 verl/GRPO。

## 二、五个设计点（讲设计思路的主干）

### 1. 四项 CL Loss —— 巩固目标

$$L_{cl} = \lambda_1 L_{rl} + \lambda_2 L_{kl} + \lambda_3 L_{replay} + \lambda_4 L_{ent}$$

- **设计取舍**：$L_{reg}$（参数 L2 正则）**弃用**，槽位让给 $L_{ent}$——agentic 场景里参数级正则不如行为级（熵 + replay）有效。
- $\lambda_4 = 0.001$ **全程固定**防 Echo Trap，不参与消融。
- $L_{kl}$ 用 **reverse KL** $D_{KL}(\pi_{new}\|\pi_{ref})$，锚住旧策略而非追平。
- **工程关键**：零 fork 注入 verl，唯一注入点 `actor.set_loss_fn(cl_loss)` + buffer hooks。replay 行用专用 mask，**不污染 PPO 分母**。

### 2. 7 桶 Replay Buffer —— 记忆

**按能力/领域分桶，不按难度**（难度会随模型能力漂移，桶会失稳）：
Workflow / SysOps / Dialogue / Finance / Communication / Knowledge / OfficeQA（纯文本 195 任务）。

- **核心取舍 ①：priority 不用 reward 绝对值**。训练推进 reward 整体上升，按 reward 排序会系统性淘汰旧轨迹，buffer 退化成滑动窗口、丧失 CL 意义。改用**抗遗忘价值**（forgetting_risk 主导）。
- **核心取舍 ②：桶内淘汰，禁止跨桶挤出**——保证不同能力不互相侵占。
- Quota = 保底 $q_{min}$ + 平方根加权（$\alpha=0.5$），大桶得更多但不按比例膨胀。
- 两级采样（先采桶 → 桶内 priority 加权）。

### 3. U 形块权重 —— 信用分配

replay token 按**动作块**赋权，**首尾重、中间轻**（起步 $\gamma=\delta=0.88$）：

$$w_t^{(i)} = \text{normalize}\Big(\text{clip}\big(\text{priority}_i \cdot \tfrac{\gamma^{block(t)} + \delta^{K_i-1-block(t)}}{2},\ q_5, q_{95}\big)\Big)$$

- **2026-06-08 反转**：原方案是单调衰减 + final_answer 单点 boost；反转为 U 形，因为"末端的重要性不止 final_answer 一个 token 段，靠近末端的多个块都重要"——首块=早期高方差分支决策，末块=结论生成段，中间执行细节降权。

### 4. winner-sync 会话调度 —— 干净环境信号

- **动作在内、推理在外**：agent 动作在沙箱执行，策略推理走 verl。
- **16 session × 8 slot GRPO**：组内 8 槽位级一致起点，每个 query 边界同步到 winner，**绝不 kill winner**。
- **目的**：保证组内 advantage **只反映策略差异**、不被环境噪声污染。
- 随机用户环境（随机文件系统种子）防过拟合单一 workspace。

### 5. 三 agent 模拟用户 —— 干净数据信号

真实回流数据只留**会话首条 query 作种子**，后续 query 由模拟用户在线生成：

- **观察 agent**（无人设）：从 actor 输出客观判断收集了什么，产出 ObservationReport $R_t$。
- **出题 agent**（42 个独立人设，会话级随机抽 1）：据 $R_t$ 生成下一 query。
- **奖励模型**（冻结 judge）：据 $R_t$ 实际产出 + rubric 打分，抗 reward hacking。
- **解决的问题**：根除静态多轮数据的"**前提漂移**"——静态多轮数据的后续 query 假设了一个并未发生的中间状态。三方各自独立 env 抗 self-preference。

## 四、实验设计（被问就展开）

```
Phase 1 (B1)                              纯 RL 遗忘下界
   ├── Phase 2 (K1–K5, K2-R)              KL：λ₂ 扫描 / πref 锚点 / KL×Replay
   └── Phase 3 (R0-10k/25k,R3,R4,R5,R4-w,R6,R4-K)  Replay：桶结构 vs CLEAR / priority 类型 / U 形权重 / 容量
           └── Phase 4 (C1–C4)            KL × Replay 2×2 组合
                   └── Phase 5 (S1,S2)    rollout 规模 1024×8 → 4096×8
```

- 每个对照**只动一个变量**，边际贡献可归因（如 R4→R5 = 抗遗忘 vs reward priority）。
- 多轮 query 构造**不单列消融**（实验已饱和），靠过程监控 + ClawEval Multi-turn 终点验证。
- **评测**：ClawEval（195 纯文本任务），$score = s_{safety}\times(0.8\,s_{completion}+0.2\,s_{robustness})$，**Pass³**。Reward 与评测同构（同一冻结 judge），保证一致。

## 五、系统与精度

| 维度 | 方案 |
|------|------|
| 部署 | 64×H800，**分离 40 推理 + 24 训练**（Fully Async，比 Colocate 快 3–7%）；Colocate 64 后备 |
| 异步 | Fully Async Policy，`staleness_threshold=0.3`；可平滑退化为同步 |
| 精度 | **BF16 全栈** + FP32 主权重 + FP32 Adam m/v；FP8 不进主路径 |
| 奖励 | **外部冻结 LLM judge**（非规则、非 verl 内置 RM worker），`custom_reward_function` 指向 `trainer/model_reward.py`，judge 由 env 解析 |

## 六、局限与未决（诚实交底）

- **全栈 64 卡 smoke 未跑**：Loss 链路接线 bug 已审计修复 + 纯逻辑单测通过，但 replay 行真过 verl forward + packing 断言仍待集群 1-step 全栈验证。
- **U 形 / priority 权重未实证调优**：$\gamma=\delta=0.88$、$\alpha$ 起步值待 Phase 3 数据校准；v1 因缺 embedding pipeline，diversity 信号禁用（权重 $(0.5,0.25,0,0.25)$）。
- **judge 选型未定**：须用 ClawEval 人工 rubric 一致率校准；外部 judge API 地址待提供（代码零改动，走 env 注入）。
- **winner-sync 进程态保真**：平台若只支持磁盘快照，替补槽进程/内存态可能与 winner 不一致（头号 PoC 风险）。
- **27B 成本/显存数字待重算**（原按 70B 估）。
