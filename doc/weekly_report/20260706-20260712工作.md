## 一、冷采集 Pipeline（seed → 多轮轨迹 → parquet）

### 五阶段链路
- **`run_cold_pipeline.sh` / `run_w3_pipeline.sh`**：一条龙 generate → filter → collect → parquet →（warmup）。S1 生成幂等（queries 已存在跳过）。
- **打桶 + 人设 + 可跑性合并为单次 LLM 调用**：taskspec → queries.jsonl，移除静态映射全走 LLM，9 桶全覆盖零 unknown；从 42 人设按 seed_query 语义匹配最佳人设；逐条判定沙箱可跑性剔除依赖本机盘/外部通道的任务——三件事一次调用省 2/3 LLM 开销。
- **完全可插拔**：queries / taskspecs / backend / template / workspace-dir 全 CLI flag 化。
- **增量安全**：collect-mode overwrite / incremental / retry；每 10 条原子落盘 + fsync，崩溃可快速恢复。
- **数据外置**：所有采集轨迹/观察报告移出仓库到 `agentic_cl_rollouts`，按 `real/smoke × trajectory/debug × model` 分层。

### 多轮采集（actor + observer + questioner，无 reward/winner）
- actor(hermes) + observer(沙箱 diff) + questioner(persona follow-up)。
- **Hermes 沙箱集成**：workspace 文件上传 + 禁用 clarify + 跨轮 `--resume` 续接记忆 + sandbox timeout 拉长防长任务截断。
- **观测报告分流落盘**：observer reports 单独写 `observer_reports.jsonl`，与轨迹解耦。
- **只有 winner 入 replay buffer**：losers 仅供 GRPO advantage；训练时 winner 轨迹按 step 持久化 JSONL。
- **搜索工具入沙箱**：Serper + Jina `serper-search` CLI 注入 hermes 镜像，支持 research/qa 真实联网检索（镜像 build 待有 Docker daemon 环境）。

### 数据清洗（双点 + C++）
- 前端对 seed_query、后端对轨迹分别 `strip_zw`（去零宽字符）；`filter_garbled`（乱码检测 + 轨迹丢弃）。均为 C++ 二进制替代原 Python 实现提速。

## 二、人设与耐心系统

- **会话完全由 Questioner 驱动**：满意自动 `end_session`，不满意继续追问；删掉所有轮数上限 / K budget / patience 抛硬币，一个会话只做一件事。
- **耐心公式** `P_k = P0 × r^k`（r=保留率，接近 1）。P0 3~10，r 0.45~0.90：最耐心 ~22 次失败才 P<1，最没耐心 ~2 次。失败轮 patience-based 重试（kill threshold 0.01→0.1）。
- **人设更难满足**：结束前审查准确性/边界；重试用人设口吻而非机械消息；挑剔程度自然嵌入人设 profile。

## 三、Observer / 多轮对话闭环迭代（本周下半周核心，10 轮循环）

配套自建健康度工具，每轮改动都有真实采集数据实证 + 单测锁定。

### 工具
- **`analyze_observer_health.py`**：FS diff 覆盖 / 真实红旗数 / 端口噪声率 / turn 分布 / ended_by / 「满意却忽略红旗」/「红旗被跟进率」，支持多份 before/after 对比。
- **`collect_smoke.sh`**：时间戳非覆盖采集（`模型_任务类型_UTC秒`），历史不覆盖、可追溯对比。

### Observer 修复
- **两级模型 failover**（provider × model）：三角色 `providers:` 结构，外层轮换厂商、内层轮换模型；可重试错误（5xx/401/408/429/timeout/截断）跳下一模型再下一厂商，首个成功者提升为默认并持久化。根因：死端点 qwen3.7-max(502) 曾致约 1/4 questioner 调用被静默当满意 → 换 qwen3-max。
- **解除 questioner follow-up 阻塞（3 根因）**：平均轮数从 1.02（98% 秒退）恢复——探针被 hermes runtime 污染、QA 任务无 FS diff 时回退 actor 回答、questioner_error 被静默记为 end_session（区分 ended_by）。
- **报告重构：干净三分类 + 全量内容 + 去噪**（本周新）：`state_diff` 组织为「新增/改变/删除」三段——新增列新文件全文、改变列 before/after、删除列旧文件全文，doc/PPT/PDF 用插件提取文本；系统变更只留装包（删端口/进程噪声）；运行时文件（.bashrc/AGENTS.md）从 tree+diff 过滤；intermediate 去系统噪声。
- **结构化红旗** `has_red_flag`：布尔判定，文本双向重整（正向短语胜过安抚开头、否定从句消歧），修复"先安抚后报问题"被关键词过滤误吞的 bug（基线 18/216 真红旗被抑制）。
- **final 字段修复**：始终 `list[dict]`（文本回答包成 dict，不再裸 str 崩溃下游）。

### Questioner 修复
- **消费 observer 红旗**：user turn 顶部红旗 banner + 硬规则"未解决红旗压倒满意"，有具体问题时本轮禁止 end_session。
- **对照原始任务核对完整性**（本周新）：seed query 始终置顶（不受滑窗挤出），任务列 N 项/多子任务时核对交付是否全覆盖，缺失/半成品/跑题就追问。
- **轮换池收敛**：thinking 模型（deepseek/kimi）在加长 prompt 下截断激增（一批 32q 内 22 次）→ 连环 failover 致 questioner_error；移除，改为 3 个可靠非 thinking（sonnet + qwen3-max + gpt-5.4-mini），多样性靠轮换+人设+报告变化。
- **截断自适应退避（仅 reward judge）**：截断时同模型 2× 预算重试 512→4096，耗尽再换模型；questioner/observer 截断直接换模型（不烧 token）。

### 效果（真实采集，reconciled 口径）
| 指标 | 基线 | 修复后 |
|---|---|---|
| 端口/进程/运行时噪声 | 20.3% / 有 / 有 | **全 0** |
| 红旗被跟进率 | 78.6% | **94–100%** |
| 满意却忽略红旗 | 6 | **0** |
| questioner_error | 4 | **0** |
| final 裸 str 违规 | 24/82 | **0** |

observer 报告干净、内容完整、结构化定位问题；多轮对话 0 漏追问。单轮率偏高经核实是数据集 QA/闲聊/一次性任务占比高的自然结果，非缺陷。

## 关键决策
1. 桶分类：训练线全 LLM（taskspec 无官方 category），评测线静态映射 + LLM 补 user_agent。
2. 多轮驱动：Questioner 唯一控制会话长度，不用 K budget / patience 抛硬币。
3. 耐心：乘法衰减 `P0×r^k` 替代指数减法，论文叙事更清晰。
4. buffer 准入：只有 winner 入库，losers 仅供 GRPO advantage。
5. Agent 容错：两级 failover + 死端点持久化，杜绝"LLM 失败被静默当满意"的数据污染。
6. **Observer 职责边界**：只客观记录环境状态（三分类去噪 diff），不做质量审查；"交付是否满足任务要求"归 questioner（它代表用户、看得到 query）。
7. **截断退避只给 reward judge**：questioner/observer 用非 thinking 模型 + 直接 failover，不为 thinking 模型烧 token。
