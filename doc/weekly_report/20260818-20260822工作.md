主线：**reward 归因专题**——从 cl2r_baseline（r0）"reward 为什么不涨"出发，用「查得分→得分归类→低分归因→定性→判超参」的方法链，定位并修复了 write_file 写盘 bug（数据+沙箱层）、judge 反问误判两个问题，并判定 reward 不涨的决定因素是超参（lr 太小）而非 judge prompt。全过程记入 `doc/tuning/Reward_归因方法与调优经验.md`，结论并入 `Bug_Fix_精简总表.md` F7/F8。

## 1. reward 归因方法链（08-22）

从落盘数据（`rollouts/training/cl2r_baseline/rollout_status-*.jsonl` + `logs/harness/train/step-*/`）一步步查：

- **查得分趋势**：20 步 `critic/rewards/mean` 0.49±0.03、斜率 −0.0013/step → **不存在系统性下降**，是 GRPO 采样噪声，20 步太短判不出趋势。
- **得分归类**：按 reward 分档拆维度 → reward 由 **task_done 门控**决定（低分档 task_done 率仅 4%）。
- **难度交叉**：难题 reward 更低（d4=0.601 > d6=0.425），**推翻**记忆里的"难题更高"；每步难度构成逐步一致（d4:21/d5:4/d6:39）→ **每步难度均衡已实现**（F6 生效）。
  - ⚠️ 踩坑：一开始用错数据源 `train_aligned.parquet`（只匹配 346/1279）算出反向结论，改用训练真正读的 `train_cl.parquet`（100% 覆盖）后纠正。教训：归因前先确认 config 的 `data.train_files`。
- **低分归因**：读 10 条低分轨迹全文对比【指令要求】vs【实际产出】→ 77% 产出了但没达标（要求写文件却只打印摘要）、14% 环境缺输入文件、8% 反问。**judge 没系统性判严**，不能靠松 judge 抬分。

## 2. write_file 写盘 bug（F8，真机验证）

低分档 status 全 success（没崩没超时）但 task_done=0。用户猜"沙箱是否不能写盘/无权限"，**证伪**：高分轨迹能成功写 `./outputs/xxx`（沙箱能写）→ 对低分按证据分类 → 6% 是真写失败报错。

- **根因**：Hermes `tools/file_operations.py::_atomic_write` 把临时文件 `.hermes-tmp` 建在目标父目录，父目录不存在/不可写就崩——`//.hermes-tmp:Permission denied`（写根 `/`）、`/workspace/.hermes-tmp:No such file`（`/workspace` 不存在）、`./outputs/.hermes-tmp`（outputs 没建）。
- **真机复现+验证**：`scripts/verify_write_fix.py`（CPU 机起真实 e2b 沙箱，不需 GPU/模型）。探针发现沙箱用户 `user`(uid1000)、默认 cwd=/home/user、根 `/` 不可写。
- **Hermes 锁死 v2026.6.5 不能改**，从可控层修：
  - **数据层**（治本，去非必要 sudo）：`scripts/data/rewrite_workspace_path.py` 把指令里 1661 处 `/workspace`→`/home/user/workspace`（parquet+jsonl，prompt+extra_info），正则排除 `/workspaces` 复数、含中文标点后瞻。0 残留。
  - **沙箱层**：`configs/exps/agent_loop_config.yaml` 的 `init_command` = `mkdir -p /home/user/workspace /home/user/outputs; cd /home/user`（官方注入点，不碰 Hermes/verl，**无 sudo**）。
  - **hook 层**：新建 `src/trainer/mkdir_deliverable_hook.py::MkdirDeliverableHook`，复用 verl `AgentRunHook.prepare`（agent 命令前跑、持 sandbox+instruction），per-task 从本任务指令解析深层写目录 `mkdir -p` 一层层建（每任务 ~1 个、零污染）。9 单测 + 真机验证。
- 验证：改写后路径写入✅；深层子目录（`tests/`、`tcs_wave_a/frontend/js/views/`）经 hook 预建后写入✅；只剩 agent 主动写根 `/xxx`（数据不引用的坏路径）不兜、交 RL 收敛。

## 3. judge 反问分情况（F7）

`REWARD_RUBRIC`（`agents/prompts.py`）原"Non-answer/refusal → task_done=0"把**所有**反问判失败。但必要的反问（输入真缺失/需求真歧义，尤其多轮首轮）是对的，一律判 0 会教模型"宁可瞎编也不问"。

- 按用户口径改：judge 从 ENVIRONMENT DIFF+任务输入判断反问是否**必要**——必要 → task_done=1（与完成同等）；不必要（信息齐全却停滞/反复问/逃避）→ 0。
- 57 个 reward/judge 单测过。

## 4. reward 不涨判定：超参问题，非 prompt 问题

- **prompt 侧健康**：trajectory 0.27→0.81、correctness 0.10→0.90 分得开，reward_std 稳定 0.28（组内有对比信号）。
- **超参侧异常**：`actor/ppo_kl≈−0.0006` 20 步纹丝不动、`pg_clipfrac` 0.004 恒定、`lr=2e-6 constant + mini_batch=64 每步单更` → **policy 基本没离开初始点，模型还没开始学**。
- **结论**：reward 信号本身是对的，不涨的决定因素是 lr 太小。trajectory 分段打分改造**先不做**（瓶颈在超参）。
- **待调**：lr 2e-6→5e-6/1e-5、拆 mini_batch，跑到 100 步看 ppo_kl 是否离 0。

## F9 收尾（08-23，替换缺源坏行）

F9 第一轮只修了 67 个有显式 ws 路径的 review 任务。全量 `_file_ok` 扫表发现**坏行 1667 个**（coding 750 + research 917）——query 引用 `/home/user/workspace` 或 `./inputs` 读文件但文件源不存在。

**定位过程**：
- 确认文件不缺失（在 tongronglei raw ws 里），但 raw 是 parent 级、child 轨迹无 id 字段关联 → 无法确定性映射。
- 试从轨迹重建文件（方案 B：seed_query 文本匹配会话→拼 tool 输出）→ 不可信（定位靠文本匹配非确定性 id、内容未核验），废弃。
- 查清：unk_ id 题轨迹只有 messages+tools 无元数据，id 不可溯源是采集时造成；"能找到文件"靠 query 路径文本匹配（抽 gen_task_id/ws_dir）非靠 id；research d4-6 干净池=0（引用 workspace 多为产出型"为 brief 某节收集资料，Do not edit，return JSON"，不需预置文件，但路径不合理仍要换）。

**修法**（`scripts/data/replace_bad_review_tasks.py`）：
- 替换池：`new_trajectories_labeled.jsonl` 同桶 + 不在保留好行 + unique + **文件齐全**（不引入新缺源，加了 `seed2traj_taskspecs/<rid>/files` 第三查找分支）。
- 优先级：非 unk_ d4-6 → 非 unk_ d7 → unk_ d4-6 → unk_ d7（尽可能可溯源）。
- 结果：coding 750（31 非 unk_，d4 为主）、research 917（12 非 unk_，全 d7，因 research d4-6 干净池=0）。
- **替换后 0 缺源、0 重复、12800 行结构不变**。全量核验：9805 产出型（无需文件）+ 2995 读文件且源存在 + 0 缺源。

**妥协**（用户口径"实验，过拟合无所谓，认了"）：research 全 d7（难度偏难）、可溯源 id 仅 81/12800（research 可溯源题只 28 不够，禁用 dirty.bak 补）。核心目标"0 缺源、文件能找到"达成。
