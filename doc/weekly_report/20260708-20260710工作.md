## 一、Observer / 多轮对话闭环改进（本周核心）

用「代码→采集→分析→修复」循环持续打磨 observer 与多轮对话，配套自建健康度分析工具，每轮改动都有真实采集数据实证 + 单测锁定。

### 分析工具 + 时间戳采集
- **`scripts/analyze_observer_health.py`**：读 `grpo_hermes.jsonl` 打健康度——FS diff 覆盖 / 真实红旗数 / 端口噪声率 / 多轮深度分布 / `ended_by` 分类 / 「满意却忽略红旗」耦合 / 「红旗被跟进率」。支持多份对比（before/after）。
- **`scripts/collect_smoke.sh`**：时间戳非覆盖采集，目录命名 `模型_任务类型_UTC秒`（如 `gpt5_iter6_20260710T132228Z`），历史数据永不覆盖，可追溯。

### Observer 修复（07-09 + 本 session）
- **PDF 探针噪声**：抑制黑色字体标签误报（`fix(observer): PDF probe`）。
- **P0-P2 三修**：final 回填、state_diff 传给 questioner、二进制布局提取（`a9196b8`）。
- **红旗判定抗「安抚开头」抑制（结构化 has_red_flag）**：observer 常写「No empty deliverables detected. One discrepancy is present: ...」（先安抚后报问题），旧纯关键词过滤把整条当「无问题」丢弃——**基线 18/216 报告真实红旗被抑制**。改为在 `ObservationReport` 加结构化布尔 `has_red_flag` + 「正向短语胜过安抚开头」判定逻辑（单一来源 `prompts.py`）。
- **has_red_flag 双向重整**：采集数据实证 observer LLM 两个方向都会设错（漏标 + 误标，如文本明写「无红旗」却 `has_red_flag=true`），`_finalize_red_flag` 改对称重整，以文本判定为准双向覆盖模型布尔。
- **QA/只读任务丢答案**：原「fs+sys 都空才回退答案文本」，QA 任务顺带装个包（sys 非空）就不触发 → 答案丢失。改为「fs 空即回退」surface actor 回答。
- **`final` 字段 schema 违规**：QA answer surface 路径把裸字符串塞进应为 `list[dict{path,kind,content_excerpt}]` 的 `final`（实测 24/82 item 是裸 str）→ 崩溃所有 `f["path"]` 消费方。改为包成规范 dict。

### Questioner 修复
- **消费 observer 红旗**：`QUESTIONER_SYSTEM` 加硬规则「未解决红旗压倒满意」，user turn 顶部加 `⚠ UNRESOLVED RED FLAG` banner，报告有具体问题时本轮禁止 end_session。
- **轮换池降权高截断模型**：默认 `max_tokens` 512→1024（给 thinking 模型推理余量）；`configs/agents.yaml` 重排——可靠非 thinking 模型（sonnet/qwen3-max）前置、thinking 模型（deepseek/kimi）后置，减少 TruncatedOutputError 刷屏与无效 failover。
