## 一、冷采集 Pipeline（seed → 多轮轨迹）

### 数据管线（generate → filter → collect → parquet → warmup）
- **五阶段链**：`run_cold_pipeline.sh` 一条龙从 taskspec 到可训练 parquet + buffer warmup。
- **打桶（全 LLM）**：taskspec → queries.jsonl。移除静态映射，所有任务统一走 LLM 分类，9 桶全覆盖、零 unknown。
- **人设 + 桶合并为单次 LLM 调用**：从 42 人设中按 seed_query 语义匹配最佳人设，与桶分类合并为一次调用，省一半 LLM 开销。
- **可runnable 过滤并入 classify**：LLM 逐条判定沙箱可跑性，与分类合并为单次调用，剔除依赖本机盘/外部通道的任务。
- **完全可插拔**：queries / taskspecs / backend / template / workspace-dir 全部 CLI flag 化，数据源与后端可随时替换。
- **增量安全**：collect-mode incremental（默认）/ overwrite / retry；每 10 条原子落盘 + fsync，崩溃可快速恢复。

### 多轮采集（actor + observer + questioner）
- **actor(hermes) + observer(沙箱 diff) + questioner(follow-up)**，冷采集阶段无 reward/winner。
- **Hermes 沙箱集成**：workspace 文件上传 + 禁用 clarify 工具 + 跨轮 `--resume` 续接记忆 + sandbox timeout 拉到 10800s（长 agentic 任务不被截断）。
- **观测报告分流落盘**：observer reports 单独写 `observer_reports.jsonl`，与轨迹解耦。
- **只有 winner 入 replay buffer**：losers 仅用于 GRPO advantage 计算，不进 buffer；训练时 winner 轨迹按 step 持久化为 JSONL。

### 人设与耐心系统
- **会话完全由 Questioner 驱动**：满意自动 `end_session`，不满意继续追问；删掉所有轮数上限 / K budget / patience 抛硬币，一个会话只做一件事。
- **耐心公式**：`P_k = P0 × r^k`（r = 保留率，接近 1）。P0 范围 3~10，r 范围 0.45~0.90。
  - 最耐心（r=0.90）：P<1 需 ~22 次失败；最没耐心（r=0.45）：仅 ~2 次失败。
- **失败轮 patience-based 重试**：kill threshold 0.01→0.1（10%）。
- **人设更难满足**：Questioner 在结束前审查准确性/边界情况；重试用人设口吻而非机械消息；挑剔程度自然嵌入人设 profile。

### 数据清洗加固（双点清洗）
- **双点清洗**：前端对 seed_query、后端对轨迹分别 `strip_zw`（去零宽字符）。
- **C++ 二进制**：`strip_zw` + `filter_garbled`（乱码检测 + 轨迹丢弃）替代原 Python 实现，提速。

## 二、Agent 容错（关键稳定性修复）

- **两级模型 failover**（provider × model）：observer/questioner/judge 三角色改为 `providers:` 结构，外层轮换厂商、内层轮换同厂商模型。可重试错误（5xx/401/408/429/timeout/截断）跳到下一模型再下一厂商；首个成功者提升为默认并持久化（内存 + 可选磁盘），并发采集器不重复探测死端点。向后兼容旧配置。
  - **根因**：死端点 qwen3.7-max（502）曾导致约 1/4 的 questioner 调用失败，被静默当作 end_session。已换 qwen3-max 并加容错。
- **Observer 三根因修复（解除 questioner follow-up 阻塞）**：平均轮数从 1.02（98% 秒退）修复。
  1. 探针被 hermes runtime 污染（`.hermes/state.db`/日志/auth）→ SKIP 集加 `.hermes`，系统探针丢弃瞬态进程。
  2. QA/推理/roleplay 任务通过回复文本而非文件交付 → fs+sys diff 为空时回退到 actor 末条回复作 final，让 questioner 有东西可审查。
  3. questioner_error（LLM 401/timeout）被静默记为 end_session → 区分 `ended_by`，暴露真实失败。

## 关键决策
1. 桶分类：训练线全 LLM（taskspec 无官方 category），评测线静态映射 + LLM 补 user_agent。
2. 多轮驱动：Questioner 唯一控制会话长度，不用 K budget / patience coin flip。
3. 耐心：乘法衰减 `P0×r^k` 替代指数减法，论文叙事更清晰。
4. buffer 准入：只有 winner 入库，losers 仅供 GRPO advantage，保证 replay 质量。
5. Agent 容错：两级 failover + 死端点持久化，杜绝「LLM 失败被静默当满意」的数据污染。
