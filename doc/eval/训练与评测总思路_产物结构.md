## 1. 总思路一句话

**每个实验内部按桶顺序训练；每个实验训完立即评测一次并记录每桶分数；每个 Phase 内所有实验评完后对比选参、传给下一 Phase；最后一个 Phase 完成后，用最终模型 vs baseline 评测持续学习的遗忘问题。**

评测的推理**只跑一次**（每实验一次），分数固定存档；之后一切权重方案对比都是**纯数学计算**，不重跑推理（省算力）。

## 2. 训练思路

### 2.1 实验内部：按桶顺序训练

每个实验（B1 / K* / R* / C* / S* ...）**内部**都按 9 桶顺序训练，桶内任务打乱：

```
一个实验内部的时间线（以 R4 为例）:
  阶段1: 训 桶A(workflow)  ── buffer 主要回放 A
  阶段2: 训 桶B(ops)       ── buffer 回放 A（防止忘 A）
  阶段3: 训 桶C(qa)        ── buffer 回放 A、B
  ...
  阶段N: 训 桶N            ── buffer 回放 A~N-1
  ↓ 全桶训完
  得到该实验的最终 checkpoint
```

- **桶的双重身份**：桶既是 replay buffer 的组织单元（控制回放什么），**也是训练的时间阶段单元**（先训完一个桶再训下一个）。
- **为什么按桶顺序**：这是持续学习/灾难性遗忘的经典设定——"顺序学 A、B、C，看学到 C 时 A 忘没忘"。若混采训练，遗忘现象被弱化，buffer 的防遗忘价值无法体现。
- **评测组间序 = 训练组间序**（简化对齐，见评测方案 §3）。

### 2.2 CL 模型 vs Baseline

| | CL 模型 | Baseline |
|---|---|---|
| 训练 | 按桶顺序训，buffer 回放旧桶 | 按桶顺序训，**无回放** |
| 预期 | 早期训练的桶（A/B）被回放保住，分数高 | 早期桶已忘，分数低 |

### 2.3 训练起点与评测参照（2026-07-04 定案）

**所有实验的训练起点 = π₀（初始 27B），不接上个 phase 的 ckpt。** 理由：21 实验是 ablation 矩阵，可比性的生命线是"同起点、控制变量"。若接上个 phase 的 ckpt 训（继承底子），Phase 之间的对比就分不清"是本 phase 参数好还是继承的底子好"，ablation 失效。

- **上个 phase 只传"选中的超参配置"**（λ2 / replay 类型等），**不传 ckpt**。例：Phase 4 的 C1 = Phase2 选中的 λ2 + Phase3 选中的 replay 配置，但 C1 仍从 π₀ 训。
- **评测参照统一 = baseline**（无 CL、同从 π₀ 训的 27B）。所有实验的每桶 delta 都跟这同一个 baseline 算，全程可比。**不跟上个 phase 比**（起点都是 π₀，跨 phase delta 无意义）。

**"局部最优拼起来不一定全局最优"怎么办**：这是逐维搜索的固有短板（Phase2 单调 KL 最优、Phase3 单调 replay 最优，合起来可能因交互效应不最优）。解法**不是**改成接 ckpt 训（那会引入继承污染，更难拆），而是：
- **Phase 2/3 每 phase 选 top-2（非 top-1）** → 留候选对冲；
- **Phase 4（C1-C4）= top-2×top-2 的联合网格搜索**，专门验证 KL×Replay 组合是否互补/冗余——这是路线里**已内建的兜底机制**；
- 若 Phase 4 网格仍不够，Phase 6 加联合调参点兜底；
- 若"合起来确实不优"，这本身是可发表的交互效应结论。

## 3. 评测思路（两级 + 终点）

### 3.1 每个实验：训完评一次，记录固定分数

```
实验 X 训完 → 评测一次 → 记录 {S_A, S_B, ..., S_N}（每桶分数，固定不变）
```

推理结果一旦跑完就固定存档，后续所有权重方案对比都在这份固定分数上做数学计算。

### 3.2 每个 Phase 末：对比选参，传给下一 Phase

```
Phase 1 (B1)                → 建遗忘基线
Phase 2 (K1-K5, K2-R) 全评完 → 对比选 top-2 KL 配置  ─┐
Phase 3 (R0-R6, R4-w, R4-K) 全评完 → 对比选 top-2 Replay ├─→ 传参
Phase 4 (C1-C4) 全评完       → 选最优 CL 组合           │
Phase 5 (S1, S2) 全评完      → 选最优规模               │
Phase 6 (X*) 按需            → 探索                    ─┘
```

（各 Phase 的选参 gate = 验收标准，见 `CL_Update_Sunhao.md` 各 Phase「验收标准」表。）

**阶段汇总工具**：`scripts/phase_summary.py --phase-dir runs/phaseN` 自动扫本 phase 所有实验的 `eval/scores.json`，产出 `runs/phaseN/_phase_summary.json`——含每实验×每桶得分 + 跟 baseline 的 `delta_vs_baseline`（都看，不只 cl_score）+ 每桶细则 `per_bucket/*.jsonl` 的下钻索引。**不自动选 top-2**：`selected` 字段留空，@孙豪 看完每桶表现手动填。

### 3.3 最后一个 Phase 完成：终点测遗忘

```
最终模型（走完全 Phase 选参的 CL 模型）  vs  Baseline（无 buffer，同桶序训）
   → 同一评测集，按桶分组打分
   → 逐桶对比 + 加权总分
   → 权重后置（线性/指数衰减，纯数学）→ 选叙事口径
```

### 3.4 权重后置（省算力核心）

评测只跑一次得到固定的每桶分数，之后套不同权重方案（线性/指数衰减：越早训的桶权重越大）只是数学计算，不重跑推理。详见 [`防遗忘评测方案.md`](防遗忘评测方案.md) §4。

## 3.5 Buffer 如何抽取（replay batch 组成，2026-07-04 定案）

每个训练 step：`train_batch_size=1024` 条新任务 + 从 buffer 额外抽固定 `replay_batch_size=512` 条旧任务回放（**口径 A：固定条数**，旧任务约占 33%）。

**为什么固定 512（≈33%）而非 CLEAR 的 50%**：CLEAR (Rolnick 2019) 用 50%（甚至 75%）replay，但那是**小模型 + 简单任务 + 廉价样本**的场景。本项目 27B agentic 多轮，每条 replay 要过 actor 独立 forward（额外算力），且旧任务过多会淹没新任务学习。故起步 3%，**防遗忘强度靠 λ3 调（R4 0.5 → R6 0.8），不靠堆条数**（堆条数=堆算力+淹没新任务）；条数消融留 Phase 6。

**抽取 = 两级加权采样（`replay_buffer/sampler.py`）**：
1. **选桶**（`_sample_buckets`）：桶权重 = `0.7·(配额比) + 0.3·(1/9) [+ 0.1 饿死补偿]`。大桶得多、小桶保底、超 50 step 没回放的桶强制救活。**从全部非空桶抽**（含未训到的未来桶——符合"已历经若干轮 continual、buffer 本就有各能力历史"的设定；评测只评过去桶遗忘，未来桶不进度量）。
2. **桶内选轨迹**（`_sample_one_within_bucket`）：按 priority 加权随机（`priority` 模式，R4 主方案）——抗遗忘价值（forgetting_risk 0.4 + rarity/diversity/difficulty 各 0.2），**非** reward 绝对值、**非**贪心 top-k。R3 对照用 `uniform`。
3. **去重**（2026-07-04 修）：一个 batch 内 512 条**互不重复**——两级加权可能重抽同一条，`sample()` 现"抽到重复就重抽"直到凑齐 512 条 distinct（库存不足则优雅停在库存数）。

## 4. 产物存储原则

**每个实验一个自包含子文件夹**：该实验的**模型权重 + 训练参数（config 快照）+ 评测结果 + 日志**全部收在一个目录下，不散落。

- 一个实验目录 = 完整可追溯单元（拿走这个目录就有该实验的一切）。
- 顶层按 Phase 分组，Phase 下按实验分组。
- 跨实验汇总（21 张分数表 → 权重后置对比）单独存一处，指向各实验的固定分数。

目录结构详见 §5。

## 5. 产物目录结构

> 已落地（2026-07-04）。结构约定见 [`runs/README.md`](../../runs/README.md)。

**核心原则**：每个实验一个自包含子目录；权重文件太大**不进 runs**——真实 ckpt 在仓库顶层 `ckpts/<exp>/`，`runs/<phase>/<exp>/checkpoints` 软链过去。

```
ckpts/                              # 真实权重（runs 外, 顶层, gitignore）
└── <exp>/global_step_<N>/

runs/                               # 轻量：配置快照/评测/日志/汇总（gitignore, 仅 README+.gitkeep 进 git）
├── phase0/  p0-a..e   + _phase_summary.json   # 冷启动数据来源消融
├── phase1/  b1        + _phase_summary.json
├── phase2/  k1..k5,k2-r + _phase_summary.json
├── phase3/  r0-10k..r4-k + _phase_summary.json
├── phase4/  c1..c4    + _phase_summary.json
├── phase5/  s1,s2     + _phase_summary.json
├── phase6/  x*
├── baseline/                       # 无 CL 的 27B（终点对决）
└── _final/                         # 终点：持续学习遗忘对决
    ├── forgetting_report.json      # CL 最终模型 vs baseline 逐桶遗忘
    ├── cl_model/{scores.json, per_bucket/*.jsonl}
    ├── baseline/{scores.json, per_bucket/*.jsonl}
    ├── weighting/{linear.json, exponential.json, ...}   # 权重后置(纯数学)
    └── all_scores_matrix.csv       # 21 实验 × 9 桶 固定分数总表

# 单个实验目录（每实验自包含）:
runs/phaseN/<exp>/
├── config.snapshot.yaml            # 训练参数快照（start_train.sh 训前拷）
├── checkpoints -> ../../../ckpts/<exp>/   # 软链，真实权重在 runs 外
├── buffer/buffer-final.sqlite
├── eval/                           # 过程评测（该实验训完评一次）
│   ├── scores.json                 #   总账：每桶得分 + 该实验 vs baseline 两端对比 + delta
│   └── per_bucket/<桶>.jsonl        #   细则：桶内逐题 {task_id,passed_all,safety,completion,robustness,reward}
└── logs/{train.log, metrics.jsonl}
```

**代码落点**（本次落地）：
- `scripts/start_train.sh` / `scripts/run_phases.sh`：从 config 路径推 `phase`，建 `runs/<phase>/<exp>/`（config 快照 + checkpoints 软链 + logs），设 `CKPT_DIR` env。
- `trainer/cl_main.py::load_config`：读 `CKPT_DIR` env 覆盖 verl `trainer.default_local_dir`，使真实 ckpt 落到 runs 外的 `ckpts/<exp>/`（软链目标）。
- `eval/run_eval.py`：`--exp-dir runs/<phase>/<exp>` → 写 `<exp-dir>/eval/{scores.json, per_bucket/*.jsonl}`；`scores.json` 按桶聚合且含 CL vs baseline 两端。
- `scripts/eval.sh`：透传 `--exp-dir` / `--baseline-ckpt`。

**两层评测**：过程评测（`phaseN/<exp>/eval/`，每实验、phase 选参用、含两端）+ 终点对决（`_final/`，CL 最终模型 vs baseline）。
