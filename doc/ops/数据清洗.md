# 冷采集数据清洗

> 创建：2026-07-08

## 为什么需要

**前清洗（源头）**：taskspecs 采集自真实用户会话，部分数据可能含零宽字符（BOM、word joiner、软连字符等）。这些字符进入 seed_query 后会被 hermes 携带进后续对话，污染整条轨迹。

**后清洗（训练）**：hermes/observer/questioner 调用 LLM 时可能引入或透传零宽字符。训练阶段这些不可见字符会造成 tokenizer 异常、embedding 噪声、diff 误判等问题，影响训练稳定性。

## 清洗范围

| 字符 | Unicode | 字节序列 | 来源 |
|------|---------|----------|------|
| WORD JOINER | U+2060 | `E2 81 A0` | 文本编辑器的不可见连接符 |
| ZWNBSP / BOM | U+FEFF | `EF BB BF` | 文件头 BOM 残留 |
| SOFT HYPHEN | U+00AD | `C2 AD` | 浏览器/Word 的软换行标记 |

三类字符均**无可见语义**——删掉不会改变文本含义。

## 清洗流程

```
Stage 1: 前清洗 (Python)
  _load_one_taskspec()
    → seed_query = strip_zw(taskspec.seed_query)
    → 写入 queries.jsonl
  覆盖范围: 2849 条 seed_query
  耗时: 毫秒级

Stage 2: 后清洗 (C++)
  stage_collect() 完成全部采集后
    → bin/strip_zw < grpo_hermes.jsonl > tmp
    → tmp 替换原文件
  覆盖范围: 2849 条轨迹, 全部 message content
  耗时: 秒级（65KB 缓冲块 + O3 优化）
```

## 实现

- **Python `strip_zw()`**：`str.translate({0x2060:None, 0xFEFF:None, 0x00AD:None})`，位于 `data/cleaning.py:33`
- **C++ `bin/strip_zw`**：独立二进制，无依赖，UTF-8 字节流遍历，3 种零宽字符精确定位删除。源码 `GarbledDataDetection/cpp/src/strip_zw_standalone.cpp`
- **管线集成**：前清洗在 `scripts/run_cold_start.py::_load_one_taskspec`，后清洗在 `stage_collect` 末尾 pipe 调用
