# 完整流程：从数据到训练

> 2026-07-08。两条管线（冷采集 + 训练）的完整描述，含数据流、计算流、关键差异。

## 一、数据准备（开发机，离线）

**从上游 taskspec 开始**——3878 个任务，每个一份 `taskspec.yaml`（含 seed_query、task_family）+ 一份 `files/`（工作区文件）。

### S1 前清洗 + 打标 + 人设

```
taskspec.yaml → seed_query → strip_zw (去零宽) → garbled 检测 → 有脏就丢弃
→ LLM 一次调用同时给出 {bucket, persona_name}（sufy, 32 并发, 全覆盖）
→ datasets/queries.jsonl (3878 条)
```

### S1b 剔除不可跑任务

```
filter_unrunnable.py → LLM 判沙箱可行性
→ E:\盘、真实飞书通道等 → 丢弃 1029 条
→ queries.jsonl 最终 2849 条
```

### S2 冷采集（多轮, actor + observer + questioner）

```
每条 query 一个独立沙箱（10800s 生命周期）：
  - 从 queries.jsonl 获取预选人设
  - 上传 workspace 文件到沙箱
  - hermes 配置（禁 clarify）+ sufy 模型
  - 多轮循环（完全由 Questioner 控制）：
      hermes chat → 沙箱执行工具 → 产出文件
      → observer 对比沙箱 before/after diff → 客观报告
      → questioner 基于报告 + 人设 → follow-up 或 <end_session>
      → 失败时 patience P0·r^k 决定是否重做
  - hermes --resume 跨轮续接对话记忆
  - 全程无 reward/judge/winner（那是训练阶段的事）
→ rollouts/cold_start/grpo_hermes.jsonl (2849 条多轮轨迹)
```

### S2b 后清洗（C++ 二进制）

```
bin/strip_zw | bin/filter_garbled
→ ZW 字符去除 + 脏字符 >5% 轨迹丢弃
→ 最终清洗后轨迹
```

### S3 转 parquet

```
trajectory_to_parquet.py
→ 取轨迹 messages 的 system + 首个 user（种子 query）→ prompt
→ 丢弃 assistant 回复（verl 会在线重新 rollout，保证 on-policy）
→ bucket/persona 信息进 extra_info
→ 98:2 切 train/val
→ datasets/{train,val}.parquet
```

### S4 warmup buffer

```
warmup_buffer.py
→ 轨迹按 bucket 分组入 9 桶 BucketReplayBuffer
→ 桶内优先级排序（抗遗忘价值, 不用 reward 绝对值）
→ buffer.sqlite 落盘
```

## 二、训练（GPU 集群，在线）

**一个训练 step 的全貌：**

```
train.sh configs/phase1/b1.yaml
  → trainer/cl_main.py
    → _preload_warmup() → buffer.load(warmup.sqlite)  # 冷启动轨迹预填
    → CLTaskRunner → verl PPO/GRPO
```

### ━━━ 每 step ━━━

**1. verl 读取 batch (1024 条 prompts)**

每条 prompt 来自 `train.parquet`（源头已清洗）

**2. verl lightllm rollout（本机 Qwen3.6-27B）**

对每条 prompt：8 路并行 rollout → 8 条轨迹
产出：token_ids + log_probs（π_old）+ response_mask

**3. 多轮会话（如 4 轮 × 8 路 = 32 条）**

```
Turn 1: 8 条 → GRPO 组内归一化 (per-uid) → winner → 正史纠正
Turn 2: 8 条 → 组内归一化 → winner → 正史纠正
...4 轮后产生 32 条
```

**4. Judge 打分（外部 sufy 模型）**

```
三维打分：completion / safety / robustness
reward = safety × (0.8·completion + 0.2·robustness)
```

**5. 拼接 replay batch（从 buffer 采 512 条旧任务轨迹）**

```
_append_replay_rows() → 拼进 RL batch（is_replay=True, response_mask=0）
```

**6. original_update(batch) —— 全量 GRPO 训练**

```
├─ π_new 前向 → log_prob
├─ importance ratio = exp(log_prob - old_log_prob)
├─ × advantage (per-uid 组内归一化)
├─ CL Loss = λ1·L_rl + λ2·L_kl + λ3·L_replay + λ4·L_ent
│    - L_rl: PPO clipped loss（32 条全参与）
│    - L_kl: 逆向 KL 约束策略漂移
│    - L_replay: 旧任务的行为克隆（512 条 replay, response_mask=0）
│    - L_ent: 熵正则防 Echo Trap（λ4=0.001, 全部配置开启）
└─ backward → 梯度更新
```

**7. Post: 轨迹处理**

```
├─ strip_zw → 去零宽
├─ winner (max reward per task_id) → buffer.add_trajectory()
│    loser 贡献完梯度后被 GC 回收，不进 buffer
└─ _persist_winners → rollouts/training/<exp>/step-N.jsonl
     （会话级正史拼接：4 轮 winner 消息拼成 1 条）
```

**8. Post: 周期操作**

```
├─ buffer.stats() → wandb 指标
├─ buffer.dump() → buffer_dumps/<exp>-step-N.sqlite（快照）
└─ forgetting_risk → compute_replay_current_logprobs → 回填优先级
```

## 三、关键差异：冷采集 vs 训练

| | 冷采集 | 训练 |
|---|---|---|
| actor | 沙箱内 hermes → sufy | 本机 Qwen3.6-27B → lightllm |
| 提问方式 | Questioner 人设追问 | 同上（逻辑复用） |
| GRPO | 无（1 query = 1 trajectory） | 8 路 per query |
| reward/judge | 无 | 有（sufy judge） |
| winner 选取 | 无（只有一条） | max reward per task_id |
| 正史纠正 | 无 | per-turn winner sync |
| 轨迹用途 | 入 buffer 防遗忘 | 全量用于 L_rl，winner 入 buffer |
| 环境 | 腾讯沙箱（E2B） | GPU 集群（训练卡） |
