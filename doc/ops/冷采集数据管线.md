# 冷采集数据管线

> 从 taskspecs 到训练可用的 parquet 数据，四阶段 + 清洗贯穿。
> 一键全跑：`bash scripts/run_cold_pipeline.sh --all-collect`
> 采集引擎 `scripts/run_cold_start.py`（打标 + 多轮采集，tqdm 进度条）
> 沙箱引擎 `scripts/sandbox_grpo_collect.py`（hermes 生命周期 + observer + questioner）

## 全链路

```
═══════════ Stage 1: 前清洗 + 打桶 + 人设 ═══════════

data/taskspecs/ (3878)
  │ _load_one_taskspec():
  │   seed_query → strip_zw (Python, 3种ZW) → garbled>0? → DROP
  │
  ├─ task_family 静态映射 6 种 (318条) → 直接打桶
  └─ 其余 (3560条) → LLM classify (sufy gpt-5.4-mini, 32并发)
       → 再 LLM 选人设 (42选1, 32并发)

▼ datasets/queries.jsonl  {record_id, queries, bucket, persona_name}

═══════════ Stage 2: 冷采集 (多轮) ═══════════
run_cold_start.py --no-generate --num-queries 2849 --max-concurrent 32

每条 query:
  persona = 预选人设
  起沙箱(10800s) → 上传workspace files → hermes配置(AGENTS.md禁clarify)
  → patience_tracker = PatienceTracker(P0, r)
  → 多轮循环 (Questioner 控制):
      hermes chat -q [--resume sid] → observer(沙箱diff)
      → 成功: questioner.next_query → follow-up 或 <end_session>
      → 失败: pt.on_failure() → P_k = P0·r^k → redo 或 patience_exhausted
      → redo: questioner 用人设语气追问
  沙箱销毁

  写入: incremental(跳过已成功), 每10条原子落盘

▼ rollouts/cold_start/grpo_hermes.jsonl
  {query_index, messages, bucket, persona_name, num_turns, ended_by}

═══════════ Stage 2b: 后清洗 (C++) ═══════════
bin/strip_zw < grpo_hermes.jsonl | bin/filter_garbled --garble-threshold 0.05 > cleaned
  strip_zw:     删除 U+2060/U+FEFF/U+00AD (不丢行)
  filter_garbled: Unicode 字符分类 → garble>5% → DROP 整条轨迹

═══════════ Stage 3: 轨迹 → parquet ═══════════
trajectory_to_parquet.py
  messages → system+首个user → prompt; bucket 透传; 98:2 切 train/val
▼ datasets/{train,val}.parquet

═══════════ Stage 4: warmup + 训练 ═══════════
warmup_buffer.py → buffer.sqlite → train.sh → verl CL Loss → ckpts/
```

## 清洗

| 层 | 工具 | 语言 | 字符 | 丢弃策略 |
|----|------|------|------|----------|
| 前清洗 | `strip_zw` + `analyze_text` | Python | U+2060/U+FEFF/U+00AD + 脏字符 | any garble → DROP query |
| 后清洗-ZW | `bin/strip_zw` | C++ | U+2060/U+FEFF/U+00AD | 不丢行，仅去字符 |
| 后清洗-脏 | `bin/filter_garbled` | C++ | Unicode Cf/Cs/Co/Cn + 阿拉伯扩展等 | garble>5% → DROP 轨迹 |

## 多轮会话控制

- 会话长度：完全由 Questioner 控制（满意→end_session，不满意→追问），无固定预算
- 失败重做：PatienceTracker `P_k = P0·r^k`，P≤0.1 斩杀
- hermes 上下文：`--resume` 跨轮续接对话记忆 + 沙箱文件持久
- clarify 禁用：AGENTS.md + terminal.timeout=60

## 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--max-concurrent` | 32 | 沙箱并发数 |
| `--slot-timeout` | 900 | 单轮 hermes 超时 (s) |
| `--hermes-max-turns` | 30 | hermes 内部 ReAct 步数上限 |
| `--collect-mode` | incremental | overwrite / incremental / retry |
| `P0` | 3~10 | 人设初始耐心 |
| `r` | 0.45~0.90 | 人设耐心保留率 |
| garble-threshold | 0.05 (后) / 0 (前) | 脏字符容忍度 |
