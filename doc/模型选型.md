## 1. Endpoints（统一配置）

- **远程（tokenhub，SenseTime 内网，OpenAI 兼容）**：base `https://tokenhub.sensetime.com/v1`；key 取自外部凭证文件（本仓库不存真实 key）。用于 actor(远程对照)/observer/questioner。
- **本地 Judge**：`scripts/serve_reward_model.sh` 起一个**冻结**的 vLLM OpenAI endpoint（默认 `:8100`，served name `reward-judge`）。`JUDGE_MODEL_PATH` 指模型路径。
- **smoke / 无凭证**：`scripts/mock_judge.py`（`JUDGE_MODEL=mock-judge`）+ `scripts/phase1/run_smoke.sh` 默认 mock，跑通链路不依赖真实模型。

---

## 2. 选型约束（为什么这么选）

- **三套独立 env 端点**（`OBSERVER_*` / `USERSIM_*` / `JUDGE_*`）→ observer / questioner / judge 互不为同一模型，**抗 self-preference**（同一模型既观察又出题又阅卷会偏袒自己）。
- **Observer 温度 0**：客观取证，确定性。
- **Questioner 温度 0.9**：多样性，抗 follow-up 模式坍缩。
- **Judge 冻结 + ≥ 策略容量**：reward 必须是不变的尺子（跑数周/多实验测遗忘，避免版本漂移污染遗忘度量）；judge ≥ 27B 策略以抗 reward-hacking → 默认 32B。判分对象 = ClawEval 三维 rubric（`safety*(0.8·completion+0.2·robustness)`），与评测同构。

---

## 3. Judge 校准与 serve（澄清：可选验证，非阻塞）

- **serve（必需）**：训练前用 `scripts/serve_reward_model.sh` 把选定的 judge 起成 OpenAI 兼容 endpoint，并设 `JUDGE_API_BASE/MODEL/KEY`。这是"让 reward 能调到模型"的运行前置，不是选型。
- **一致率校准（可选）**：`scripts/calibrate_judge.py` + `eval/judge_agreement.py` 可在有 ClawEval 人工标注数据时，量化"judge 打分 vs 人工"的一致率（MAE / pearson / kappa / F1，按桶分解），用于**验证**所选 judge 是否够格、或在候选间挑最小达标模型。
  - **这不是选型阻塞**：选型由 @孙豪 拍板（已定 32B 默认）。校准只是上集群后**可选的质量验证**；标注数据（@杨益博 manifest）到位就能跑，没到位也不影响用既定 judge 开训。
