## 1. 我们的方案（会前已讨论定下的）

### 1.1 一句话

**持续强化学习**：离线用 8 路 GRPO + winner-sync + reward judge 做高质量 RL 训练；线上数据进来后，提取用户首个有意义任务（"seed query"），重建 workspace，走同一套离线 RL 流程更新策略。**让线上问题逼近离线训练质量，而非离线降级去匹配线上约束。**

### 1.2 关键设计选择（去掉了哪些、留了哪些）

| 决策 | 结论 | 理由 |
|---|---|---|
| RL 是否参与策略更新 | ✅ **保留** $L_{rl}$（PPO loss） | 去掉 RL 退化为纯防遗忘系统，论文做不厚；CLEAR 2019 就做了 BC+replay，没有 RL 只是弱化版 |
| 线上是否需要 8 路 GRPO | ❌ 不需要 | 线上单条轨迹直接进 buffer，不做 winner-sync |
| judge 是否保留 | ✅ 保留（离线打分 + 冷启动筛选） | 离线 8 路靠 advantage 做策略梯度，线上单条靠 judge 裸分辅助 |
| reward 信号来源 | 离线：GRPO advantage；线上：judge 裸分 + buffer replay 历史 winner 轨迹（行为克隆锚定） | 单条 judge 噪声大，buffer replay 提供稳定方向 |
| 从线上数据提取什么 | **用户的首个有意义任务**（"seed query"），不是任意一条消息 | 首个任务 = 用户真正的需求锚点；后续 follow-up 由 questioner 在线生成 |

### 1.3 完整架构

```
离线训练（高质量信号）：
  吴健重建的 task（seed_query + workspace + hidden_goal）
   → 8 路沙箱 GRPO
   → winner-sync → winner 轨迹入 7 桶 buffer
   → L = λ₁ L_rl（PPO, advantage-weighted）+ λ₂ L_kl + λ₃ L_replay + λ₄ L_ent

线上上线后（持续微调）：
  用户会话 → 提取首个有意义任务（"seed query"）
   → 1 路沙箱执行
   → judge 打分
   → 轨迹入 buffer
   → L = λ₁ L_rl（judge 裸分）+ λ₂ L_kl + λ₃ L_replay（含离线 winner 轨迹做历史锚）
```

### 1.4 损失函数

$$L_{cl} = \lambda_1 L_{rl} + \lambda_2 L_{kl} + \lambda_3 L_{replay} + \lambda_4 L_{ent}$$

| 项 | 作用 | 离线 | 线上 |
|---|---|---|---|
| $L_{rl}$ | 策略优化 | GRPO advantage（高信噪比） | judge 裸分（降权重，buffer replay 锚定） |
| $L_{kl}$ | 防策略漂移 | 保留 | 保留 |
| $L_{replay}$ | 从 buffer 重放历史轨迹 | 保留 | 保留（优先采离线 winner 轨迹） |
| $L_{ent}$ | 防坍缩 | 0.001 固定 | 0.001 固定 |

## 2. 跟天阔需要对齐的核心事项

### 2.1 RL 的定位（最关键）

| | 天阔思路（按纪要推测） | 我们思路 |
|---|---|---|
| RL 的作用 | 只采集轨迹，不参与策略更新 | **RL 参与策略更新** |
| 训练信号 | 纯行为克隆（BC from buffer） | $L_{rl}$（PPO）+ $L_{replay}$（BC 当锚） |
| 论文贡献 | 防遗忘系统 | 持续强化学习系统 |
| 系统复杂度 | 低 | 高（但故事也强） |

**待跟天阔确认**：他倾向"RL 只采集轨迹"是工程简化考虑，还是有更深的技术判断？

### 2.2 线上数据的用法

- **我们的设计**：从线上会话中提取用户的**首个有意义任务**（"seed query"），而非任意 query。拿到 seed query 后，重建 workspace，按离线 RL 流程训练。后续 follow-up 由 questioner 在线生成（模拟用户追问）。
- **跟天阔对齐**：这个"首个有意义任务"的提取，是吴健的数据 pipeline 做，还是天阔/乃榕那边做？目前的 14 条 taskspec 就是按这个逻辑自动生成的（`meta.source=real_feedback`），格式是否满足天阔预期？

### 2.3 线上环境恢复问题

- **问题**：RL 训练依赖完整环境（workspace 文件系统），线上用户一发 query 就走了，当时的文件状态没人存档。
- **我们的立场**：现阶段**先线下验证算法有效**，环境恢复是 Phase 2 的事。线上可以先不做 RL 更新（只采集轨迹入 buffer 做 replay），等基建到位后再开 RL。
- **待跟天阔对齐**：他有没有环境恢复的方案或时间线？"用轨迹重建 workspace"这一步谁负责？

### 2.4 验证路径：怎么证明方案有效

- **流程**：吴健重建 task（含 seed_query + workspace） → 孙豪跑算法验证 → 判断模型是否变好
- **待定**：success criteria 是什么？
  - ClawEval 195 任务 benchmark 分数？
  - 7 桶能力退化曲线（forgetting_risk 在 buffer 里的变化）？
